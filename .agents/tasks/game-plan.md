# 게임 기획안 — 수목감별 기반 학습 게임

작성일: 2026-10-19
전제: 운영비 0원(정적 호스팅) · 백엔드 없음 · 비상업(NC 사진 포함) · 모바일 우선
기반 자산: 기존 `tree-quiz` 프로젝트의 수종 데이터 120종, 사진 953장, FSRS·채점·셔플 로직, PWA 배포 파이프라인

---

## 1. 한 줄 요약

사진을 보고 수종을 맞히는 **수목감별**을, 점수·연승·제한시간·랭킹이 있는 **아케이드 퀴즈 게임**으로 만든다.
학습(기존 앱)과 재미(게임)를 분리하되 데이터·로직은 공유한다.

## 2. 목표

- 가볍게 즐기면서 자연스럽게 120종을 익히게 한다(학습 동기 부여).
- 한 판 1~3분, 결과 공유 가능(바이럴).
- 추가 비용 없이 기존 정적 배포 구조에 그대로 얹는다.

## 3. 타깃 / 플랫폼

- 조경기능사 수험생 + 식물에 관심 있는 일반인.
- 웹(PWA), 모바일 우선. 설치 없이 링크로 바로 플레이, 홈 화면 추가 시 오프라인.

---

## 4. 핵심 게임 모드

### 4.1 타임어택 (메인)
- 제한시간 60초. 사진 보고 4지선다 or 초성 입력으로 최대한 많이 맞히기.
- 정답 +점수, 연속 정답 콤보 배수(x1→x2→x3…). 오답 시 콤보 리셋·시간 -2초.
- 끝나면 점수·정답 수·최고 콤보·틀린 수종 요약.

### 4.2 서바이벌 (목숨제)
- 목숨 3개. 틀리면 1개 소모, 0이면 끝. 뒤로 갈수록 제한시간 짧아지고 혼동 수종(같은 속)이 보기에 더 자주 등장(난이도 상승).
- "몇 종까지 버텼나"가 기록.

### 4.3 스피드 매칭 (부위 맞추기)
- 잎/수피/꽃/열매 사진 카드를 같은 수종끼리 짝 맞추기(메모리/페어 게임).
- ※ 전제: 현재 사진 부위 태그가 대부분 'whole'이라, 이 모드는 **부위 태깅 보강이 선행**돼야 함(리스크 항목 참고).

### 4.4 일일 도전 (Daily Challenge)
- 날짜를 시드로 모두에게 **같은 10문제** 출제 → 점수 비교의 공정성 확보.
- 하루 1회, 결과를 이모지 그리드(예: 🟩🟩🟥🟩…)로 공유(워들 스타일).

### 4.5 대결 모드 (비동기 PvP, 선택/후순위)
- 내 플레이 기록(시드+점수)을 링크로 공유 → 상대가 같은 문제로 플레이해 점수 비교.
- 백엔드 없이 **URL 파라미터에 시드 인코딩**으로 구현(서버 불필요).

---

## 5. 게임 시스템

- **점수**: 정답 기본점 + 남은시간 보너스 + 콤보 배수 + 난이도 가중(희귀·혼동 수종 가점).
- **콤보/연승**: 연속 정답 시 배수 증가, 오답/시간초과로 리셋.
- **난이도 곡선**: 초반 쉬운(혼동 적은) 수종 → 후반 같은 속·혼동 그룹에서 오답 보기 구성(기존 `pickDistractors` 재사용).
- **힌트(선택)**: 과·상록/낙엽 등 1개 공개(점수 차감).
- **배지/업적**: 첫 올콤보, 50종 정복, 7일 연속 플레이 등(로컬 저장).
- **랭킹**:
  - 기본은 **로컬 최고 기록**(IndexedDB, 서버 0원).
  - 전역 랭킹이 필요하면 선택적 백엔드(아래 10번).

---

## 6. 콘텐츠 / 데이터

- 기존 `data/species.json`(120종) + `public/photos`(953장) 그대로 사용.
- 게임용 메타 추가 필드(선택): `rarity`(희귀도=가점), `difficulty`(혼동 그룹 크기 기반 자동 산출).
- 사진 출처·라이선스 표기 의무 유지(게임 화면에도 작게, 결과/출처 페이지에 전체).

---

## 7. 기술 설계

- 스택: 기존과 동일(Vite + React + TS + PWA). 게임은 같은 저장소의 별도 라우트/엔트리로.
- 재사용 모듈: `shuffle`(Fisher-Yates·연속중복 방지), `distractors`(오답 보기), `matching`(정답·별칭·오타), `data`(수종/사진), `storage`(IndexedDB).
- 신규 모듈: `game/engine`(점수·콤보·타이머·상태머신), `game/seed`(날짜/공유 시드 → 결정적 문제 생성), `game/scoring`.
- 결정적 RNG(시드 기반)로 일일 도전·대결의 공정성 보장(이미 테스트에서 seeded RNG 사용 중).
- 상태: 한 판은 유한 상태머신(ready → playing → feedback → ... → result).
- 접근성·모바일 우선 유지, 효과음/햅틱은 선택(음소거 기본, 토글 제공).

### 디렉터리(안)
```
src/
  game/
    engine.ts        # 상태머신·타이머·점수
    scoring.ts       # 점수/콤보/보너스 규칙(+테스트)
    seed.ts          # 날짜/공유 시드 → 결정적 문제 세트(+테스트)
    modes/
      TimeAttack.tsx
      Survival.tsx
      DailyChallenge.tsx
  views/GameHome.tsx  # 모드 선택
```

## 8. UX / 화면 흐름

1. 게임 홈: 모드 선택 + 오늘의 도전 + 내 최고기록.
2. 플레이: 사진 크게, 타이머 바, 콤보 표시, 보기/입력.
3. 즉시 피드백: 정답/오답 애니메이션 + 짧은 구분 포인트 1줄.
4. 결과: 점수·정답률·최고 콤보·틀린 수종 → "복습하기"(기존 약점 집중으로 연결) + "공유하기".
5. 공유: 점수/이모지 그리드 + 링크(시드 포함) 복사.

→ **게임과 학습의 선순환**: 게임에서 틀린 수종이 기존 앱의 약점 집중/FSRS에 반영되도록 저장 공유.

---

## 9. 배포 / 운영비

- 기존과 동일: GitHub Pages 또는 Cloudflare Pages, 운영비 0원.
- 전역 랭킹 없이 가면 **완전 0원** 유지.
- 도메인만 선택적 비용(연 1~2만원).

---

## 10. 전역 랭킹이 필요할 때 (선택지, 0원 우선)

| 방법 | 비용 | 특징 |
|---|---|---|
| 로컬 기록만 | 0원 | 서버 불필요, 기본값 |
| Cloudflare Workers + D1/KV | 무료 티어 내 0원 | 점수 저장 API, rate limit, 어뷰징 방지 필요 |
| Supabase(무료 티어) | 0원~ | DB·인증 제공, 한도 초과 시 과금 |

- 랭킹 도입 시 **점수 조작 방지**(서버 검증 or 서명된 리플레이)가 핵심 과제.

---

## 11. 리스크 / 선결 과제

- **사진 부위 태그 부족**: 현재 대부분 'whole'. 4.3 매칭 모드와 "부위별 퀴즈"는 **태깅 보강 선행 필요**(iNat annotation 연동 또는 수동 검수 UI).
- **사진 수 편차**: 히어리 1장 등 → 특정 모드에서 노출 조정 필요.
- **라이선스**: NC 포함 → 상업화·광고 수익화 불가(비상업 유지). 게임이라도 동일.
- **난이도 밸런싱**: 콤보·시간 보너스 수치는 플레이 테스트로 조정.
- **중독성 vs 학습**: 재미에 치우쳐 학습 효과가 희석되지 않게, 결과→복습 동선 강조.

---

## 12. 개발 단계 (제안)

1. **MVP**: 타임어택 1모드 + 점수/콤보 + 결과 화면 + 로컬 최고기록. (기존 로직 재사용으로 빠름)
2. **v1**: 서바이벌 + 일일 도전(시드) + 공유(이모지 그리드) + 배지.
3. **v1.5**: 비동기 대결(URL 시드), 사진 부위 태깅 보강 후 매칭 모드.
4. **v2(선택)**: Cloudflare Workers 전역 랭킹 + 어뷰징 방지.

각 단계마다 단위 테스트(scoring/seed 결정성) + 브라우저 검증 + 의미 단위 커밋.
